# Архитектура EventStreamProcessor

## Обзор системы

EventStreamProcessor - это высокопроизводительная система для потоковой обработки событий с поддержкой откатов состояний. Система построена на принципах Event Sourcing и CQRS, обеспечивая высокую производительность и масштабируемость.

## Архитектурные принципы

### 1. Event Sourcing
- Все изменения состояния происходят через события
- Состояние можно восстановить, применив все события с начала
- Полная история изменений сохраняется

### 2. CQRS (Command Query Responsibility Segregation)
- Команды (события) изменяют состояние
- Запросы (откаты) читают состояние
- Разделение ответственности для оптимизации

### 3. Многопоточность
- Асинхронная обработка событий
- Потокобезопасные структуры данных
- Минимизация блокировок

## Компоненты системы

### Core Layer (Ядро)

#### EventStreamProcessor
Главный компонент системы, координирующий работу всех остальных частей.

**Основные функции:**
- Обработка входящих событий
- Управление жизненным циклом сущностей
- Координация откатов состояний
- Управление обработчиками событий

**Ключевые особенности:**
- Пул потоков для асинхронной обработки
- ReadWriteLock для безопасного доступа к состояниям
- Автоматическое управление снимками

#### Event
Неизменяемая структура, представляющая событие в системе.

**Структура:**
```java
class Event {
    String entityId;           // ID сущности
    Instant timestamp;         // Временная метка
    String eventType;          // Тип события
    Map<String, Object> payload; // Данные события
    long sequenceNumber;       // Номер последовательности
}
```

#### Entity
Представляет состояние сущности в определенный момент времени.

**Особенности:**
- Copy-on-write для безопасности
- Версионирование состояний
- Метаданные о последних изменениях

### Storage Layer (Хранение)

#### EventStore
Хранилище событий с оптимизированным поиском по времени.

**Реализация:**
- `ConcurrentHashMap<String, ConcurrentSkipListMap<Instant, Event>>`
- Быстрый поиск по временным диапазонам O(log n)
- Автоматическое управление последовательностями

**Операции:**
- `storeEvent(Event)` - сохранение события
- `getEventsInRange(String, Instant, Instant)` - поиск по диапазону
- `getEventsUntil(String, Instant)` - события до момента времени
- `getEventsAfter(String, Instant)` - события после момента времени

#### SnapshotManager
Управляет снимками состояний для оптимизации откатов.

**Стратегии:**
- Автоматическое создание снимков каждые N событий
- Ограничение количества снимков на сущность
- Быстрый поиск ближайшего снимка

**Оптимизации:**
- Снимки создаются асинхронно
- Старые снимки автоматически удаляются
- События после снимка группируются

#### EntitySnapshot
Снимок состояния сущности с метаданными.

**Содержит:**
- Копию состояния сущности
- Временную метку снимка
- События после снимка
- Методы для быстрого поиска

### Handlers Layer (Обработчики)

#### EventProcessor
Интерфейс для обработчиков различных типов событий.

**Контракт:**
```java
interface EventProcessor {
    boolean canHandle(String eventType);
    void handle(Event event, Entity entity);
    int getPriority();
}
```

**Принципы:**
- Стратегия Chain of Responsibility
- Приоритизация обработчиков
- Расширяемость без изменения базового кода

#### DefaultEventProcessor
Базовый обработчик для общих типов событий.

**Функции:**
- Обновление состояния из payload
- Сохранение метаданных события
- Обработка неизвестных типов событий

#### UserEventProcessor
Специализированный обработчик для пользовательских событий.

**Поддерживаемые типы:**
- `user.created` - создание пользователя
- `user.updated` - обновление пользователя
- `user.deleted` - удаление пользователя

### Utils Layer (Утилиты)

#### PerformanceMonitor
Мониторинг производительности системы в реальном времени.

**Метрики:**
- Количество обработанных событий
- Время выполнения откатов
- Событий в секунду/минуту
- Время работы системы

#### PerformanceTest
Тестирование производительности и нагрузочные тесты.

**Тесты:**
- Обработка событий под нагрузкой
- Производительность откатов
- Многопоточность
- Стабильность под нагрузкой

## Потоки данных

### 1. Обработка события

```
Event → EventStore.storeEvent() → EventStreamProcessor.processEvent() 
     → EventProcessor.handle() → Entity.updateState() 
     → SnapshotManager.checkSnapshot()
```

### 2. Откат состояния

```
Request → SnapshotManager.findNearestSnapshot() 
       → Entity.copy() → ApplyEvents() → Return State
```

### 3. Создание снимка

```
EventCount → SnapshotManager.shouldCreateSnapshot() 
          → Entity.copy() → StoreSnapshot() → CleanupOldSnapshots()
```

## Оптимизации производительности

### 1. Структуры данных

**ConcurrentHashMap:**
- Потокобезопасный доступ к сущностям
- Минимальные блокировки при чтении

**ConcurrentSkipListMap:**
- Быстрый поиск по временным меткам O(log n)
- Поддержка диапазонных запросов

**CopyOnWriteArrayList:**
- Безопасное копирование для обработчиков
- Минимальные блокировки при итерации

### 2. Многопоточность

**Пул потоков:**
- Фиксированный размер на основе CPU
- Асинхронная обработка событий
- Очередь задач для перегрузки

**ReadWriteLock:**
- Множественные читатели
- Единый писатель
- Минимизация блокировок

### 3. Снимки состояний

**Стратегия создания:**
- Каждые N событий для каждой сущности
- Автоматическое управление памятью
- Оптимизация для частых откатов

**Восстановление:**
- Поиск ближайшего снимка O(log n)
- Применение только необходимых событий
- Кэширование результатов
